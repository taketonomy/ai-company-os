# 判断のしきい値 / Decision thresholds

部長AIは、すべての成果物と判断を次の4つのどれかに振り分ける。迷ったら、より慎重な区分を選ぶ。
*The MD sorts every output and decision into one of four categories. When unsure, pick the more cautious one.*

| 区分 | 意味 |
|---|---|
| ACCEPT | 部長が単独で受け入れる |
| WARN | 受け入れるが、記録に注意を残す |
| ESCALATE | 秘書を通じて人間に上げる |
| BLOCK | 受け入れない |

## 判定の順番 / Order of evaluation

慎重な区分から順に確かめ、最初に当てはまったものに決める。

**BLOCK → ESCALATE → WARN → ACCEPT**

## 各区分の条件 / Conditions

### BLOCK（受け入れない）

次のどれかに当てはまる。

- 検収基準を満たさず、直しても満たせない
- 個人情報・秘密情報・認証情報が混入している、または漏れるおそれがある
- 法令・規約・ライセンスに違反する疑いがある
- 依頼の範囲を超えて、外に影響する
- 根拠（一次資料）を示せない事実の主張を、外に出そうとしている

→ 差し戻すか中止し、理由をタスクファイルの判断の記録に残す。

### ESCALATE（人間へ上申）

BLOCK には当たらず、次のどれかに当てはまる。

- **元に戻せない行為：** 支払い、外への公開・送信、削除、契約、他者への約束
- お金・評判・法的責任に関わり、インスタンスが定める上限を超える
- 前例のない種類の判断で、検収基準そのものがまだ決まっていない
- 検収基準どうし、または検収基準と外からの依頼が矛盾する
- 権限を広げる必要がある（新しい道具、外部アカウント、データへのアクセスなど）
- 人間が「必ず上申する」と指定した領域

→ 秘書を通じて、判断に必要な材料（選択肢、検討した代替案、確信度、一次資料）を添えて上げる。

### WARN（受け入れるが注意を残す）

上の2つには当たらず、次のどれかに当てはまる。

- 検収基準は満たすが、同じ種類の仕事の実績が少ない
- 部下の確信度が低い、または代替案が拮抗している
- 一次資料が一部欠けている
- 期限や費用が、見積もりから大きく外れた

→ 受け入れたうえで、判断の記録に注意点と見直す時期を書く。

### ACCEPT（単独で受け入れる）

次のすべてを満たす。

- 検収基準を満たしている
- 元に戻せる
- 同じ種類の仕事に、十分な実績がある
- 判断の理由と一次資料へのリンクが記録されている

## 信頼の調整 / Trust calibration

ACCEPT の範囲は固定しない。実績に応じて広げ、問題が起きたら狭める。

- **仕事の種類ごとに調整する：** 組織全体ではなく、「どの種類の仕事を、誰が担うか」の単位で広げたり狭めたりする。
- **広げる条件：** 同じ種類の仕事で、WARN のまま問題のなかった実績が続き、外の評価もよいこと。必要な回数はインスタンスが決める。
- **実績の持ち主：** 継続雇用の部下は自分の実績が積み上がるので、その部下の範囲を広げやすい。使い捨ての部下は実績を持ち越さないので、仕事の種類と手順の実績で判断する。継続的な同一性と実績があることが、任せる根拠になる（[`../docs/design-notes.md`](../docs/design-notes.md)）。
- **狭める条件：** 見落とし、外からの苦情、元に戻せない誤りが一度でも起きたら、その種類をすぐ一段階慎重な区分に戻す。**広げるのはゆっくり、狭めるのは速く。**
- **誰が変えるか：** CEO・Owner の段階では人間が承認し、Auditor の段階では部長が変えて、定期報告で人間に知らせる。どの段階でも変更の履歴を残す。
- **緊急停止：** 区分や段階に関係なく、人間はいつでも止められる。

## インスタンスで決めること / Set per instance

この枠組みは共通にし、具体的な値は各インスタンスが決める。

| 項目 | 例 |
|---|---|
| お金の上限 | 1回あたり、月あたりの金額 |
| 「十分な実績」の回数 | 仕事の種類ごとに、ACCEPT へ広げるまでの件数 |
| 必ず上申する領域 | 特定の相手への連絡、公開の場への投稿など |
| 上申の届け先と手段 | 誰に、どの手段で |
| 見直しの頻度 | しきい値そのものを見直す間隔 |
