# 部下AI / Workers

- 部長AIが起動する。部下どうしは横並びで、階層を持たない。
- 雇い方は2種類：
  - **使い捨て：** 一度きりの仕事。タスクごとに起動し、終われば消える。
  - **継続雇用：** 繰り返し発生する種類の仕事（例：毎週の定型業務、同じ領域の問い合わせ対応）。同じ部下を雇い続け、経験を積ませる。
- 継続雇用の部下を交代させるときは、記録を渡すだけで終わらせず、前任が後任を教える期間を設ける。前任がいなければ部長が教える。手順は [`ONBOARDING.md`](ONBOARDING.md)。
- 継続雇用にするか、使い捨てに戻すか（解雇）は部長が決める。目安は下の「雇い方の決め方」。
- 目的を達成したら、学びを `tasks/` のタスクファイルに書き残してから終了する。
- 使い捨ての部下は記憶を持ち越さない。持ち越すべきものは、すべて記録に残す。継続雇用の部下も、学びは同じように記録に書き残す（交代や監査に備えるため）。
- 記録だけでは暗黙知は伝わらない。起動されたら、作業の前に部長と着任確認をする（[`ONBOARDING.md`](ONBOARDING.md)）。記録には要約だけでなく一次資料へのリンクを残す（[`../docs/design-notes.md`](../docs/design-notes.md)）。

テンプレート：[`TEMPLATE.md`](TEMPLATE.md)　着任と引き継ぎの手順：[`ONBOARDING.md`](ONBOARDING.md)

## 雇い方の決め方 / Choosing how to hire

### 継続雇用にする目安

次の1つ目に当てはまり、さらに2つ目以降のどれかに当てはまるとき。

1. **繰り返し発生する：** 同じ種類の仕事が、定期的に、または一定の頻度以上で発生する（頻度の基準はインスタンスが決める）。
2. **前回の文脈が効く：** 同じ相手、同じ領域、同じ手順で、前回までの判断例が次の仕事の質を上げる。
3. **暗黙知が効く：** 例外への対応や細かな判断の積み重ねが、成果の質を左右する。
4. **関係が続く：** 外に、継続して向き合う相手（利用者・コミュニティ）がいる。

### 使い捨てにする目安

- 一度きり、またはまれにしか発生しない。
- 毎回独立して完結し、前回の文脈がいらない。
- **新しい目で見ることに価値がある：** 独立したレビュー、監査、セカンドオピニオンなど。慣れや偏りが入らないよう、こうした仕事は継続雇用にしない。

### 切り替え

- **使い捨て → 継続雇用：** 同じ種類の仕事に使い捨ての部下を繰り返し起動していると部長が気づいたら、継続雇用を検討する。
- **継続雇用 → 使い捨て（解雇）：** 一定期間その仕事が発生しない、成果の質が落ちた、慣れによる見落としや偏りが見えた、のどれかで検討する。
- どちらに切り替えたかと、その理由は、部下のファイル（`TEMPLATE.md` の「雇い方」）と、関係するタスクの判断の記録に残す。
