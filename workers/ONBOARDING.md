# 着任と引き継ぎ / Onboarding and handover

記録を渡すだけでは、暗黙知は伝わらない（[`../docs/design-notes.md`](../docs/design-notes.md) の「記録は歪む」）。このファイルは、部下が仕事を始めるときと、継続雇用の部下が交代するときの手順を定める。
*Handing over records is not enough. This file sets the procedure for starting work and for replacing a retained worker.*

## 1. 着任確認（すべての部下）/ Onboarding check (every worker)

### 部長が渡すもの

- タスクファイル（目的・検収基準）
- 一次資料へのリンク（会話の記録、ログ、差分、外からの依頼の原文）
- 関連する過去のタスクと、その判断の記録
- 使ってよい道具と、[`../md/thresholds.md`](../md/thresholds.md) で特に注意する点（ESCALATE になりそうな行為）

### 部下が自分の言葉で返すもの

1. 目的：何ができれば完了か
2. 検収基準：何を満たせば受け入れられるか
3. 前提と不明点：少なくとも1つは挙げる。「不明点はない」で済ませない
4. 最初の区切り：最初にどこまで作り、いつ検収を受けるか
5. 上申が必要になりそうな行為：元に戻せない行為、権限の拡大など

### 部長の判断

- ずれがあれば直し、もう一度説明させる。一致したら作業を始めさせる。
- 着任確認でのずれと修正は、タスクファイルの判断の記録に残す。後の着任確認を改善する材料になる。

### 原則

- 着任確認なしに作業を始めない。
- 記録を読んだだけで「わかった」としない。説明できて初めて着任とする。

## 2. 最初の区切りで検収する / Accept the first increment early

最初の区切りは小さくし、早めに検収する（[`../md/README.md`](../md/README.md) の検収サイクル）。ずれは早く見つけるほど直しやすい。

## 3. 引き継ぎ（継続雇用の部下の交代）/ Handover (replacing a retained worker)

交代の理由が解雇・配置換え・モデルの更新のどれであっても、同じ手順で行う。

1. **前任が書き残す：** 担当している仕事の一覧、繰り返しの手順、よくある例外とその判断例、うまくいかなかったこと、未完了の件。どれも一次資料へのリンクをつける。
2. **後任が着任確認をする：** 上の「着任確認」を、前任を相手に行う。
3. **並行期間：** 後任が実際の案件を処理し、前任がそれを確認して、実際の判断を通じて教える。マニュアルより、実例で教えることを優先する。必要な件数や期間はインスタンスが決める。
4. **部長が交代を決める：** 後任が前任と同じ水準に達したと部長が判断したら、交代する。前任は終了するか、別の仕事に移る。
5. **信頼は引き継がない：** 実績は個々の部下に付く。後任の ACCEPT の範囲は前任と同じにせず、一段階慎重な区分から始め、[`../md/thresholds.md`](../md/thresholds.md) の「信頼の調整」で広げていく。

### 前任がいない場合

部長が教育係になる。過去のタスクファイルと一次資料から代表的な事例を選んで後任に説明し、最初の数件は部長が細かく検収する。

## 未解決 / Open

- **部長自身の交代：** 部長は組織で唯一ずっと残る層だが、モデルの更新などで入れ替わることはありうる。そのとき、誰がどう教えるか（人間か、前任の部長か）はまだ決めていない。
