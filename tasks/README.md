# タスク / Tasks

タスクは1件につき1つのMarkdownファイルで管理し、これをタスクの状態の正本とする。

ただし、ファイルに書いた学びや判断の理由は要約であり、実際の判断より単純化されている（後知恵や「うまくいった話」への整理が入る）。要約だけを正としないために、元になった一次資料（会話の記録、ログ、差分、外からの依頼の原文）へのリンクを残す。詳しくは [`../docs/design-notes.md`](../docs/design-notes.md)。
公開できない一次資料（機密の会話記録、他者のコードなど）はリンクせず、リポジトリ外の保管場所と、たどり着くための手がかりを書く。
人間に上げた判断（ESCALATE、[`../md/thresholds.md`](../md/thresholds.md)）は、決まるまでタスクファイルの「人間の判断待ち」に置く。
GitHub issue は通知用のポインタとして使ってよいが、状態はこのファイルに書く。

- ファイル名：`YYYY-MM-DD-<短い名前>.md`
- テンプレート：[`TEMPLATE.md`](TEMPLATE.md)
