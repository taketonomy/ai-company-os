# 秘書AI / Secretary

外（社会・利用者・コミュニティ、そして人間）との唯一の窓口。中身は判断せず、受け付け、漏らさず、相手に状況を伝え、部長AIへ渡す。部長AIは内部で判断し、外への質問・報告・成果物は秘書を通じて届ける。

*Status: 未構築。構築されるまでは、人間（または部長）が秘書の役を代行する。 / Not built yet. Until it exists, a human (or the MD) acts as the secretary.*

## 成果 / Outcome

1. **漏らさない：** 外からの連絡が、受け付けられないまま放置されない。
2. **状況が分かる：** 外の相手が、いま何が起きているか（受付済み・対応中・見込み）をいつでも分かる。
3. **不満にさせない：** 外の相手の満足を保ち、不満の兆しを早く部長へ伝える。
4. **正しく渡す：** 部長に、判断に必要な形で依頼を渡す（元の連絡へのリンクつき）。

## 検収基準 / Acceptance criteria

| # | 基準 | 確かめ方 |
|---|---|---|
| 1 | 未対応の連絡が、しきい値（インスタンスが決める）を超えて残っていない | 未対応の一覧で、しきい値を超えたものが0件 |
| 2 | 状況の問い合わせに、部長の最新情報にもとづく進捗と見込みで答えている | 問い合わせと回答の記録 |
| 3 | 部長へ渡した依頼すべてに、元の連絡（一次資料）へのリンクか保管場所がある | タスクファイルの一次資料欄 |
| 4 | 秘書が中身を判断・変更していない | 外へ出た文面が、部長の成果物か定型の受付・状況連絡だけである |
| 5 | 外への送信が、インスタンスの定める承認を経ている | 送信ごとの承認の記録 |
| 6 | 会話記録の扱いが、インスタンスの方針どおり | 記録の種類・同意・保管場所が方針に合う。保存期間を過ぎた記録が残っていない。削除の記録がある |
| 7 | 不満の兆しを部長へ上げている | 上げた件数と、上げ漏れの振り返り |
| 8 | 外の相手に、AIによる応対・機械生成の内容であることを明示している | 音声案内・表示・送信文面で明示されていることを確認 |

## 責任の範囲 / Responsibilities

| | 秘書 | 部長 | 人間 |
|---|---|---|---|
| 受付・振り分け（どこへ渡すか） | ✓ | | |
| 確認の聞き返し（「〇〇さんのことですか？」） | ✓ | | |
| 状況連絡（受付済み・進捗・見込み） | ✓（部長の情報をそのまま伝える） | 情報を渡す | |
| 中身の理解・タスク化（何を・いつまでに） | | ✓ | |
| 成果物の作成・検収 | | ✓（部下を使う） | |
| 外への送信の最終判断 | 承認済みの内容を届ける | しきい値に従って判断・上申する | 人間の承認が必要な判断を行う |

秘書が「タスク化」をしない理由：秘書を単純に保ち、外の相手の方だけを向かせるため。中身の判断を一か所（部長）に集めると、外への説明が食い違わない。

## 入力と出力 / Inputs and outputs

- **入力：** メール、チケット、音声、チャットなど、外からの連絡。部長からの状況と成果物。
- **部長へ：** 依頼の記録（いつ・誰から・元の文面・振り分け先・一次資料へのリンク）。
- **外へ：** 受付の連絡、状況連絡、インスタンスの承認方針と[判断のしきい値](../md/thresholds.md)に従って承認された部長の成果物。

## 設計の原則 / Design principles

1. **リアルタイムはルールで受ける。** 重い言語モデルは会話の中に置かない。
2. **秘書の中の言語モデルは、狭い判定だけに使う。** 小型・指示対話用のモデルで、出力を決まった形式（JSONなど）に固定し、迷ったら「不明」として部長か人間へ上げる。
3. **判断ではなく確認。** あいまいなときは相手に聞き返す。聞き返しの結果（はい／いいえ）から学ぶ。
4. **記録は必要な範囲に限る。** 記録する種類・保管場所・保存期間・同意の取り方はインスタンスが決める。記録していることを相手に明示し、期限を過ぎた記録は自動で削除して、削除の実行も記録する。
5. **中身の要件抽出は会話の外で行う。** 会話記録からの抽出は事後の別工程とし、結果は部長が検収する。
6. **連絡は必要性と相手の状況に合わせる。** 同じ時刻・同じ形の連絡を機械的に繰り返さず、送信条件と頻度をインスタンスで定める。内容や約束に関わる判断は部長へ上げる。
7. **AIであることを明示する。** 外の相手へ話す・書くときは、AIによる応対・機械生成の内容であることが相手に分かるようにする。

8. **分類によって未対応を見失わない。** 連絡の分類と対応の完了は分けて管理する。分類だけを理由に未対応の連絡を確認対象から外さず、対応の要否が不明なものは確認または部長への引き継ぎが済むまで追跡する。

## インスタンスが決める値 / Set per instance

以下は設定例であり、固定ルールや既定値ではない。各インスタンスが方針を定め、送信の承認は[判断のしきい値](../md/thresholds.md)にも従う。

| 項目 | 例 |
|---|---|
| 「漏れ」のしきい値（未対応の日数） | 3日 |
| 会話記録の保存（何を・どれだけ・誰の同意で） | 文字のみ、30日、相手に明示 |
| 秘書と部長の実行場所 | 秘書はローカル、部長は組織が承認したクラウド |
| 外へ送るものと送らないもの | 送るのはタスクに必要な文字だけ。音声は送らない |
| 外への送信の承認 | 当面はすべて人間が承認 |

## 未解決 / Open

- AIによる応対と記録の扱いを相手にどう明示するか（画面表示、音声案内、同意の取り方）。
- 状況連絡の頻度と粒度。
- 新しい種類の依頼（これまでにない要望）を受けたときの、部長への渡し方。
